## 统一时间线

- 不区分电脑数量，不设置 S1～S4 / S8 电脑槽位。
- 网页录音、开发板录音和 S7 转写文字保存在同一条时间线，按服务端时间排序，最新消息显示在最上方。
- 网页和开发板发送语音，S7 将小智识别的用户文字逐条加入时间线；已有文字和未完成的旧版文字继续保留、补传。S6 小智对话不写入时间线。文字不参与扬声器播放、音频下载或语音 ZIP，网页不提供文字输入或文字转语音。
- “开发板已播放”只在扬声器完整播放并完成 DMA 尾音后回执；网页播放或中断播放不会标记已读。
- 云端最多保留 5000 条已提交消息（语音或文字），语音每条最长 20 秒，文字每条最多 1000 个 UTF-16 单元。满额时淘汰最早的开发板录音或已读语音，保护未读网页留言；如果 5000 条全部是未读网页留言，新发送会提示先播放。

S5/S6/S7 短按在松手时执行，不等待双击窗口，也没有双击查询动作。连续两次短按分别按录音、对话或转写的启停状态处理。S4 继续设置倒计时；S7/S8 及旋钮不再提供测量编辑入口。

S1、S2、S5 和旋钮的长按阈值为 3 秒，S3 为 1.2 秒。S4、S6、S7 未定义长按动作，按住后松开仍作为一次短按处理；S8 没有功能动作。

每次 S2 开始播放后，S1 都从这条语音往前回听。例如 S2 播放第 5 条，连续按 S1 播放第 4、3 条；再按 S2 播放当前第一条未读（例如第 6 条），下一次 S1 就播放第 5 条。完整播放后的已读回执保留回听位置，中断播放仍不会标记已读。

尚未建立回听位置时，S1 以第一条未读为参照播放它的前一条；全部已读时从最新一条历史语音开始回听。没有任何消息时提示“暂无语音”。

S5 在录音中或“录音结束，短按 S5 发送，长按 S5 取消”提示播放期间优先执行录音控制，不会被通用提示音打断逻辑吞掉。取消已暂存录音时只释放本次录音的槽位；已经开始发送的录音继续按原有流程重试。

每日闹钟保存在板端 NVS，依赖一次有效的网络时间同步。倒计时使用板端单调时钟，断网仍可运行。开发板时间固定使用中国标准时间 UTC+8。

## S6 小智实时语音对话

短按 S6，开发板连接小智并开始收音。用户说话由服务端断句，小智回答通过板载扬声器播放；回答播完后自动继续听，保持会话并支持多轮交谈，无需每轮按键。对话不受普通录音的 20 秒时长限制，服务端可能有自己的空闲或会话限制。

当前通过小智 `listen.start` 的 `auto` 模式轮流说话：收到小智回答时暂停麦克风采集；同时等到服务端 `tts.stop` 和本地播放缓冲、DMA 尾音完成后，才发送下一轮 `listen.start` 并恢复收音。回答期间用户说话不会采集，需等回答播完再说。旋钮旋转可调整音量，音量提示及到点闹钟、倒计时播报延后，避免设备录入自己的提示音。

再次短按 S6，在松手时立即停止收音和回答播放，再异步关闭会话；连接过程中也可这样取消。S6 不等待 S7 转写使用的 20 秒尾句窗口。对话期间其他功能键和旋钮按压被忽略，松手也不触发普通动作。

小智对话与 S7 转写、网页实时监听、普通录音互斥；网页监听已开启、录音或发送繁忙时拒绝开始对话，保留当前任务。小智对话中的新监听请求也不会开启另一条麦克风路径。S6 不控制网页实时监听开关。S6 对话中的用户识别文字和小智回答均不发送到网页时间线，已有转写文字和旧版未发完的文字继续保留、补传。

上行使用 16 kHz 单声道、60 ms 帧的 Opus。下行校验服务端协商的音频参数，再通过 Opus 解码器输出 16 kHz 单声道 PCM 供板端流式播放；采集和播放使用有界缓冲。网络中断、协议或音频处理失败、缓冲溢出时停止会话并提示失败，重新短按 S6 可重试。缓冲用于网络调度，不提供离线对话或录音恢复。

固件 0.4.17 将 Opus 编解码放入使用独立 48 KiB PSRAM 栈的任务，避免原任务栈不足引起崩溃；网络与 NVS 操作继续使用内部 RAM 栈，满足 Flash 操作期间的缓存限制。音频任务在有音频 I/O 时释放互斥锁后主动 `taskYIELD()`，让同优先级的上传任务取得锁，避免首帧上传后一直等待音频状态；空闲时保留原有延时，不给每个音频块增加整 tick 等待。

小智沿用开发板保存的 Wi-Fi，需要开发板直接联网，蓝牙网关不能代替小智连接。首次使用通过小智官方 OTA 接口获取激活信息；若需要绑定，会播报激活码并在串口显示。在 `xiaozhi.me` 添加设备并填写该验证码，完成后再次短按 S6 开始对话。固件只使用 OTA 返回的连接及激活配置，不安装其中的官方固件；若只有 MQTT 配置而没有安全 WebSocket 地址，会提示连接失败。

需要更换网络时，在非录音、非小智对话或转写状态长按旋钮 3 秒，手机连接 `EasyInput-Setup-` 加设备 MAC 后四位的热点（密码 `easyinput`），打开 `http://192.168.4.1`，填写 2.4 GHz Wi-Fi 名称和密码后保存；已有云端配置时，云端配对码可留空。热点开放 2 分钟。小智验证码与 EasyInput 云端配对码用途不同。

对话期间测量、记账和汇总的后台同步及相关 NVS 确认延后，退出后重试；旧版待发送文字仍使用原稳定编号与确认机制补传。小智账号绑定、识别断句、回复声音、多轮收听与播放切换必须由实板联网验收，不能由编译或本地测试证明。

## S7 持续语音转文字

短按 S7 后，开发板通过已绑定的小智连接持续发送语音，使用 `listen.start` 的 `realtime` 模式。识别结果在接收期间就逐条发送到共享时间线；服务端可分成多句，过长结果再按最多 1000 个 UTF-16 单元及 3000 个 UTF-8 字节拆成多条。这里只保留用户识别文字，不播放小智 TTS 或保存本轮音频。网络和首次绑定要求与 S6 相同。

再次短按 S7 立即停止麦克风，将已采集的尾帧发完，并最多接收 20 秒尾句结果。识别任务终止后，再等待本轮文字的网页显示确认，期限为 12 秒。至少得到一条识别文字、且本轮全部文字都在至少一个已挂载的网页聊天组件提交到 DOM 后得到回执，才播报“成功”。没有识别文字、发生错误、只有部分文字送达或回执期限到时播报“失败”；云端保存成功本身不算网页送达。

使用时需打开新版网页的“语音”页。设备页、尚未打开聊天页的连接不会发显示回执；回执表示文字已提交到聊天组件，不表示用户已经阅读。网页回执丢失时会有限重试，断线重连后可重新确认。S7 开始提示期间快速再按会取消并播报失败；停止后的尾句或回执等待期间再按 S7 不会新开会话。S7 与 S5 普通录音、S6 小智对话、网页实时监听互斥。

失败后未确认文字保留在原 FIFO 中继续后台补传，文字后来送达也不会补播“成功”；只要队列未完全满，旧待发文字不阻塞再次短按 S7 开始新一轮。统计边界设在引擎实际接受新一轮开始时，开始提示期间也可能补传旧文字。旧文字的 ACK 先从旧队列消耗，不增加本轮显示确认数；本轮成功只比较本轮识别数、确认数及本轮未确认数，不以整个历史队列是否清空作为成功条件。稳定消息编号用于去重；已写入 `stt/pending` 的队首可跨重启补传，后续多条队列仍在 RAM，不能保证本轮全部文字或音频断电恢复。

状态 `voice.stt` 的 `received_texts`、`acked_texts` 分别统计本轮识别和显示确认的消息条数；`session_queued_texts` 是 FIFO 总数扣除旧轮剩余条数后，本轮实际仍在队列中的未确认条数，`queued_texts` 则包含旧轮和本轮全部待发文字。显式取消清空队列后，本轮队列数可为 0，但不会伪造已显示 ACK。`stage` 可区分 `delivery.no_text`、`delivery.offline`、`delivery.display_timeout`、`delivery.engine_failed` 和 `delivered`；若已有首个引擎错误，其阶段和错误码优先保留，不被后续交付结果覆盖。开始提示取消或引擎拒绝时不执行最终交付诊断回写；引擎开始错误保留，例如 `start.unavailable`、`start.busy`、`start.queue_full`。

## 已有血压与血糖记录

S7/S8 的测量编辑、双击查询和旋钮粗细调整入口已移除。已有板端 `health/history_v1` 数据及最多 64 条待同步历史保留，联网后继续通过 Wi-Fi 或选中的蓝牙网关补传；云端按稳定编号去重，收到确认并完成本地存储后才移出队列。不会因停用按键删除历史或补造旧测量。

设备页「下载历史 CSV」继续导出云端已同步的全部测量记录，包含编号、测量时间、时间状态、人物、项目、数值、单位、接收时间和开机后毫秒数。血糖单位为 mmol/L，血压为 mmHg；时间为 UTC ISO 格式。未校准设备时钟的测量时间留空并注明未知，接收时间不冒充测量时间；板端待同步数量仍单独显示。

## 灯效

WS2812 点亮亮度固定为最低档 1%。所有红色慢闪统一为亮 0.5 秒、熄灭 2 秒，周期 2.5 秒。

| 灯 | 行为 |
| --- | --- |
| 灯 1 | 有未读语音时红色慢闪；批量已读确认期间常亮；全部已读或无记录时熄灭 |
| 灯 2 | 录音时红色常亮；发送或待重试时红色慢闪 |
| 灯 3 | 实时监听时红色慢闪；其他情况熄灭 |
| 灯 4 | 有电脑端语音页面在线时红色慢闪；无人在线或开发板未联网时熄灭 |
| 灯 5 | 已设置闹钟时红色常亮；倒计时运行中红色慢闪；倒计时优先 |

## 录音与离线重试

录音结束先写入 `voice_outbox` Flash 分区，再上传。该分区包含 8 个固定录音槽，每槽最多 20 秒；缓存满时拒绝开始新录音，保护已有录音。

每条录音使用稳定消息 ID。云端确认完整提交后才释放缓存；上传失败或等待回执超过 12 秒后，每 3 秒重新协商并续传。确认入群后释放录音并播报“发送成功”。缓存写入失败时保留 PSRAM 中的录音并提示保持供电。

满 20 秒自动结束但用户尚未再次短按 S5 时，录音已保存但不启动上传；再次短按 S5 后才开始发送，长按 S5 3 秒可取消本次暂存录音。

## 实时麦克风

- 网页“打开实时麦克风 / 关闭实时麦克风”直接启停板载麦克风，是共享房间开关，默认关闭；其他网页同步状态。
- S7/S8 不控制网页实时监听开关，S8 已停用。为避免录音路径冲突，监听期间 S1～S5 暂停操作，S6/S7 不会开始小智对话或转写；已有普通录音、小智对话或 S7 转写时拒绝打开实时麦克风。
- 板端通过二进制 WebSocket 帧发送 16 kHz 单声道 PCM16，每 20 ms 一帧、320 个采样。
- 板端在同一有序 WebSocket 上同步发送 `realtime.start`，随后立即发送实时音频；云端 ACK 仅用于诊断。网页使用约 60 ms 抖动缓冲播放。
- 实时缓冲超过约 250 ms 时丢弃旧队列，避免延迟持续累积。
- 实时音频只通过语音房间转发，不写入云端历史或 Flash。
- 网页关闭开关、开发板 Wi-Fi 直连断开或心跳超时都会停止采集并同步关闭状态；启动 8 秒未成功会取消打开请求。
- 当前 PCM16 实时流要求开发板通过 Wi-Fi 直连云服务；蓝牙网关仍可承载历史语音和状态，但不承载实时音频。

## 提示音

提示音使用 `edge-tts-chinese` 生成后裁掉首尾长静音并转换为 8 kHz 单声道 μ-law。常规提示沿用云健男声 `zh-CN-YunjianNeural`、语速 `+35%`；既有音量数字沿用晓晓女声 `+20%`。闹钟时间和倒计时分钟使用完整短语，打包为 `prompts.bin`。S7 结束使用成功或失败提示；既有测量提示素材保留，但不再由 S7/S8 或旋钮编辑触发。

重新生成：

```sh
python3 scripts/build-voice-prompts.py
```

上游许可见 [EDGE_TTS_LICENSE.txt](EDGE_TTS_LICENSE.txt)。

## 网页

网页只保留两个入口：

- **语音**：统一时间线、网页录音、实时监听状态及开关、S1～S8 操作说明。新增「下载全部语音 ZIP」和「顺序播放全部」；全部指云端当前保留的最多 5000 条语音，与网页已经加载的页数无关。网页首屏显示最新 50 条，可点击「加载更早消息」继续翻页；总条数和未读数覆盖整个群。ZIP 每包最多 100 条，文件按全局顺序和 UTC 时间命名；第一包完成后点击「下载第 N 包」继续。失败可重试当前包。连续播放先取得完整历史索引，再从最早到最新逐条下载播放，支持随时停止，网页播放不改变开发板未读状态。导出开始后新到的语音留待下次；若期间旧语音被清理会提示重试。
- **设备**：显示每日闹钟、倒计时、实时监听状态，以及血压血糖历史和记账历史 CSV 下载。USB、蓝牙连接按钮及状态集中放在折叠的「连接 Wi-Fi 与语音服务」配置区，顶部仅保留开发板在线状态和网页版本。

网页已移除手工文字输入、电脑槽位、灯光编辑、音频测试、性能、存储、分区、输入事件流和演示模式。

## 验证边界

软件检查应覆盖 S5 普通录音启停与长按取消、S6 对话启停和取消连接、S7 持续转写与快速取消、尾帧和尾句窗口、多条文字拆分、网页渲染回执及去重重试、失败后新一轮开始、旧新 ACK 计数隔离、诊断首错保留、成功失败判定、S8 停用，以及旧版记录的存储和补传兼容性。WebSocket 文本及二进制分片、下行音频播放与结束处理仍需回归。网页类型检查、构建和 ESP-IDF 固件编译分别验证对应软件产物；它们不证明实板断电保存、小智账号绑定、联网识别或语音听感。实际通过的检查以本次执行结果为准，不沿用旧固件的测试数量作为 S7 验收。

以下保留完整实板验收清单，不能用编译或自动化测试代替。本次已验证的小智对话范围见开头记录，其余场景仍需分别确认：

1. 灯 1～5 的实体顺序、1% 最低亮度和统一慢闪节奏。
2. S1 连续回听更早语音、S2 重设回听起点、播放中一次按键切换的行为，以及 S3 旋钮方向。
3. S2 完整播放后的已读回执与中断播放不标已读。
4. S5 首次短按录音、再次短按发送、录音中/满 20 秒后长按取消、快速连续两次短按、Flash 缓存和发送成功提示；旧记账待同步记录及 CSV 导出仍可用。
5. 每日闹钟跨重启保存、NTP 时间同步和到点提示。
6. 倒计时每秒滴答、每分钟长滴答与剩余分钟播报。
7. 网页直接开关实时麦克风、声音延迟、断续、底噪，以及监听与 S6/S7 的互斥。
8. S6 首次绑定、开始对话、小智回答播放、尾音结束后恢复收音、多轮交谈、旋钮调音量，以及连接中、收音中、回答中再次短按立即结束。检查断网失败提示、快速启停、与网页监听或普通录音的互斥，且对话内容不进入时间线。
9. S7 连续说话、多句文字入聊天记录、停止后的尾句、无小智回答播放、旋钮调音量、快速开始取消及等待期再次按键。分别验证全部网页显示后的成功、空结果/断网/聊天页未打开/部分未送达/回执超时后的失败；失败后补传不补播成功。确认 S8 和旧测量编辑入口停用，历史补传与 CSV 导出保留。
10. 共享 GPIO8 电源、麦克风声道、扬声器音量以及录音回放音质。
11. 先关闭聊天页让一轮 S7 显示确认失败，再次短按 S7，应仍能开始收音（完全满队列除外）；随后打开聊天页混合补传旧文字并产生新文字，核对旧 ACK 不增加新一轮 `acked_texts`、新一轮无识别时仍失败、全部新文字显示后才成功。重放旧回执不得移除新队首；对照 `queued_texts` 与 `session_queued_texts` 及交付阶段诊断检查计数。

### 容量说明

5000 条均录满 20 秒时，云端原始压缩音频约 800 MB，另加数据库与索引开销；下载的 WAV 总计约 1.6 GB，分包保存。实际可用空间和请求额度以 Cloudflare 账户套餐、用量为准，达到平台额度可能导致上传失败。建议保留需要的本地 ZIP 备份。实时监听仍不保存音频。扩容不改变开发板离线 8 条录音、64 条旧版待同步测量记录的容量。
