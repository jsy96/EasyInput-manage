# 语音时间线

本说明描述当前源码的操作和五灯规则。本文记录固件 0.4.23／网页 0.4.10 的语音行为；S5 持续上传、长语音、网页分割及 S5/S6/S7 任意键／自动停止已配套发布。网页和开发板共用同一条语音与文字时间线；S5 录音、S6 小智对话、S7 转写、S8 正计时。新版源码及固件包的构建、导出和实板验证状态见 [TESTING_PROGRESS.md](TESTING_PROGRESS.md)；旧版发布记录放在本文末尾。

2026-10-29（Asia/Shanghai）固件 **0.4.21** 已导出并烧录至身份匹配的原 ESP32-S3，保留 NVS 和录音 outbox；串口确认版本及正常启动。该版修正闹钟设置／取消失败提示和 NVS 成功后才更新运行态的顺序，清理 42 条停用提示音，保留 167 条音频的固定 ID 与原字节。网页 **0.4.8** 已部署至 `studio.leige.online`，首页、主 JS、CSS、manifest、Service Worker 均与本地构建一致；网关本轮未改动、未部署。16 个文件、130 项测试、含类型检查的网页构建和 ESP-IDF 5.5.5 构建通过。上述证据不代表按键、声音或 NVS 故障原因已完成实板验收。

## 统一时间线

- 不区分电脑数量，不设置 S1～S4 / S8 电脑槽位。
- 网页录音、开发板录音和 S7 转写文字保存在同一条时间线，按服务端时间排序，最新消息显示在最上方。
- 网页和开发板发送语音，S7 将小智识别的用户文字逐条加入时间线；已有文字和未完成的旧版文字继续保留、补传。S6 小智对话不写入时间线。文字不参与扬声器播放、音频下载或语音 ZIP，网页不提供文字输入或文字转语音。
- 网页“开发板已读”表示完整播放后的回执或手动执行全部已读；不能据此判断一定听过。网页播放或中断播放不会自动标记已读。
- 云端最多保留 5000 条已提交消息（语音或文字），网页自身录音最长 20 秒，新 S5 录音无 20 秒自动停止，文字每条最多 1000 个 UTF-16 单元。满额时淘汰最早的开发板录音或已读语音，保护未读网页留言；如果 5000 条全部是未读网页留言，新发送会提示先播放。

## 按键速查

“短按”指按下后松开；S5/S6/S7 在松手时开始，活动期间按下 S1～S8 或旋钮按键立即停止，本次按键不执行原功能，松手不补执行。没有板端语音会话时，S8 在松手时切换计时。均不等待双击窗口。

| 按键 | 操作与结果 |
| --- | --- |
| S1 短按 | 回听前一条历史语音，包括已读；连续按继续往前，到最早一条后不循环 |
| S1 长按 3 秒 | 播报全部已读确认提示；松开后再长按 S2 3 秒执行 |
| S2 短按 | 播放最早的未读语音，重设 S1 的回听起点；无未读时提示“暂无语音” |
| S3 短按 | 设置每日闹钟：默认 12:00，已有闹钟时从原值开始；右旋加、左旋减，每格 30 分钟，范围 00:00～23:30 |
| S3 长按 1.2 秒 | 取消每日闹钟 |
| S4 短按 | 设置倒计时：默认 30 分钟，右旋加、左旋减，每格 1 分钟，范围 1～60 分钟 |
| 闹钟／倒计时设置 | 每次旋转播报当前数值；数字播完后静置 3 秒自动保存。此时短按 S3 或 S4 也可立即保存当前设置 |
| 倒计时运行中 | S1～S7 或旋钮按压取消倒计时，本次按键不继续执行其他功能；S8 独立控制正计时，不取消倒计时 |
| S5 短按 | 提示结束、云端建立会话后持续录音上传；按任意键停止，尾音传完并云端保存后才显示 |
| S5 超过 20 秒 | 继续录音上传；默认一轮一条留言，由网页决定是否分割 |
| S5/S6/S7 活动中长按 | 按下即停止；S5 保存录音，不再以长按取消 |
| S5/S6/S7 自动停止 | 连续 60 秒未检测到说话，或单次达到 60 分钟。S6 思考与回答播放不计入静音时间 |
| S6 短按 | 开始小智实时语音对话；连接、收音或回答中按任意键，立即停止收音和播放并关闭会话 |
| S7 短按 | 开始持续语音转文字；按任意键立即停止收音，等待尾句和网页显示结果，再播报成功或失败 |
| S8 短按 | 从零开始正计时；再短按停止并播报总时长。下一次重新从零开始 |
| 旋钮旋转 | 正在设置闹钟／倒计时时调整数值；其余状态每格调整音量 10%，范围 10%～100% |
| 空闲时旋钮长按 3 秒 | 开启手机配网热点；不执行短按功能 |

S1、S2、旋钮长按为 3 秒；S3 为 1.2 秒。S4/S5/S6/S7 无额外长按功能；空闲时按住后松开仍按短按处理，语音活动时按下即停止。S5/S6/S7 没有双击查询或其他双击功能。

### 全部未读标记为已读

1. 保持语音服务可达，长按 S1 3 秒，听到确认提示后松开。
2. 长按 S2 3 秒；云端确认后播报成功，错误或 12 秒超时后提示失败。
3. 历史消息和音频保留，网页未读数量归零。

确认期间短按 S2，或按 S3/S4/旋钮可取消；S5～S7 暂不响应，S8 仍独立计时。灯 1 按新的接收／未读规则显示，不再用常亮表示确认状态。等待云端结果时以最终语音提示为准。

### 历史回听与播放切换

S2 每次播放都重新建立 S1 的回听起点。例如 S2 播放第 5 条，连续按 S1 播放第 4、3 条；再按 S2 播放当前最早未读（如第 6 条），下一次 S1 播放第 5 条。没有回听起点时，S1 从最早未读的前一条开始；全部已读时从最新历史开始。到最早一条后不循环。

播放中按 S1 切到前一条，按 S2 从最早未读开头播放。S3/S4/旋钮按压会先停止当前播放，本次不继续执行其他短按动作；S5/S6/S7 在松手时可直接切换至对应功能。S8 只切换正计时，不打断播放，停止后的时长等待播放空闲再播报。普通状态旋转音量也会停止历史播放并播报音量。

### S8 正计时与闹钟音乐

S8 按键松开即开始或停止计时，采用板端单调时钟，精度显示到整秒；播报启动或排队的时间不计入停止结果。停止后按需要播报小时、分钟、秒，省略为零的高位单位；不足 1 秒播报“零秒”。正计时与倒计时相互独立，可同时运行。

开始时提示“开始正计时”，停止时提示“本次计时共……”。S5/S6/S7 活动期间 S8 用于停止语音，不切换正计时；已运行的正计时继续。实时监听、其他播放或设置提示占用音频时，S8 先记录实际开始／停止时刻，等空闲再播报，不让设备把自己的提示音录入。很快停止时可跳过尚未播放的开始提示。延后播报的停止结果按顺序暂存，最多 8 次；满后拒绝新的开始，空闲时提示等待已有结果播报后重试。正计时、最后结果和待播报队列只保存在 RAM，关机或重启归零。

每日闹钟到点时，灯 2 慢闪 1 分钟，播报到点提示并播放一次约 10 秒的内置短旋律；不是循环播放 1 分钟。收音或播放繁忙时音乐延后，灯光仍从到点时开始计算 1 分钟。闹钟设置保存在 NVS，使用北京时间 UTC+8；每次开机需有效网络校时。倒计时和正计时断网仍继续，重启后不恢复。

闹钟设置或取消只有在 NVS 写入及提交成功后才更新运行状态；失败时保留内存中的原设置并播报现有的“失败”提示。串口错误日志区分 `nvs_open`、`nvs_set_u16` 和 `nvs_commit` 阶段，并包含错误名和错误码，用于排查实际存储故障。

### 功能互斥与按键暂不可用

- S5 录音、S6 对话、S7 转写和网页实时监听共用音频资源，不能同时收音。结束当前任务后再开始另一种功能。
- S5/S6/S7 的开始提示、连接、收音或 S6 回答中，按 S1～S8 或旋钮按键立即停止当前语音；该次按键只停止，松手也不执行原功能。旋钮旋转仍调音量。
- 网页实时监听期间 S1～S5 暂停操作，S6/S7 拒绝开始。需在网页关闭监听；S8 计时不受影响。
- S5 开始提示或云端建立会话前按任意键取消开始，不生成空录音。开始采集后停止会保存当前录音；尾音上传／保存期间继续按键不会取消或重开，等待云端完成。
- S7 开始提示期间按任意键会取消并播报失败；停止后的尾句及显示回执等待期间按键不会开始新一轮。
- 三种功能均在连续 60 秒未检测到说话或单次达到 60 分钟时正常结束。S6 静音只累计监听阶段，思考、回答及本地播放尾音不计入，重新监听后重新给予 60 秒；总时长继续累计。现有检测基于音量，背景噪音可能被当作说话，60 分钟上限独立生效。

## 已有记账记录

此前已移除记账输入和 S6 双击汇总入口。已有板端 `ledger` NVS 数据、云端记账记录和 CSV 导出保留；旧固件留下的待同步记录仍通过 Wi-Fi 或选中的蓝牙网关补传，云端按稳定编号去重，收到确认并写入本地存储后才移出待同步队列。

设备页「下载记账 CSV」导出云端已同步的全部记账，包含记录编号、记账时间、时间状态、金额、人民币单位、云端接收时间和开机后毫秒数。时间均为 UTC；时钟未校准时记账时间留空，接收时间另列。导出开始后新到的记录留待下一次导出，板端待同步数量单独显示。

## S6 小智实时语音对话

短按 S6，开发板连接小智并开始收音。用户说话由服务端断句，小智回答通过板载扬声器播放；回答播完后自动继续听，保持会话并支持多轮交谈，无需每轮按键。对话采用独立会话，服务端可能有自己的空闲或会话限制。

当前通过小智 `listen.start` 的 `auto` 模式轮流说话：收到小智回答时暂停麦克风采集；同时等到服务端 `tts.stop` 和本地播放缓冲、DMA 尾音完成后，才发送下一轮 `listen.start` 并恢复收音。回答期间用户说话不会采集，需等回答播完再说。旋钮旋转可调整音量，音量提示、正计时结果及到点闹钟、倒计时播报延后，避免设备录入自己的提示音。

按下任意 S1～S8 或旋钮按键立即停止收音和回答播放，再异步关闭会话；连接过程中也可这样取消，本次按键及松手不会触发其他功能。静音 60 秒或单次达到 60 分钟也按正常结束处理，不播连接失败；思考和回答播放不计入静音窗口。S6 不等待 S7 转写使用的 20 秒尾句窗口。

小智对话与 S7 转写、网页实时监听、普通录音互斥；网页监听已开启、录音或发送繁忙时拒绝开始对话，保留当前任务。小智对话中的新监听请求也不会开启另一条麦克风路径。S6 不控制网页实时监听开关。S6 对话中的用户识别文字和小智回答均不发送到网页时间线，已有转写文字和旧版未发完的文字继续保留、补传。

上行使用 16 kHz 单声道、60 ms 帧的 Opus。下行校验服务端协商的音频参数，再通过 Opus 解码器输出 16 kHz 单声道 PCM 供板端流式播放；采集和播放使用有界缓冲。网络中断、协议或音频处理失败、缓冲溢出时停止会话并提示失败，重新短按 S6 可重试。缓冲用于网络调度，不提供离线对话或录音恢复。

固件 0.4.17 将 Opus 编解码放入使用独立 48 KiB PSRAM 栈的任务，避免原任务栈不足引起崩溃；网络与 NVS 操作继续使用内部 RAM 栈，满足 Flash 操作期间的缓存限制。音频任务在有音频 I/O 时释放互斥锁后主动 `taskYIELD()`，让同优先级的上传任务取得锁，避免首帧上传后一直等待音频状态；空闲时保留原有延时，不给每个音频块增加整 tick 等待。

小智沿用开发板保存的 Wi-Fi，需要开发板直接联网，蓝牙网关不能代替小智连接。首次使用通过小智官方 OTA 接口获取激活信息；若需要绑定，会播报激活码并在串口显示。在 `xiaozhi.me` 添加设备并填写该验证码，完成后再次短按 S6 开始对话。固件只使用 OTA 返回的连接及激活配置，不安装其中的官方固件；若只有 MQTT 配置而没有安全 WebSocket 地址，会提示连接失败。

需要更换网络时，在非录音、非小智对话或转写状态长按旋钮 3 秒，手机连接 `EasyInput-Setup-` 加设备 MAC 后四位的热点（密码 `easyinput`），打开 `http://192.168.4.1`，填写 2.4 GHz Wi-Fi 名称和密码后保存；已有云端配置时，云端配对码可留空。热点开放 2 分钟。小智验证码与 EasyInput 云端配对码用途不同。

对话期间测量、记账和汇总的后台同步及相关 NVS 确认延后，退出后重试；旧版待发送文字仍使用原稳定编号与确认机制补传。小智账号绑定、识别断句、回复声音、多轮收听与播放切换必须由实板联网验收，不能由编译或本地测试证明。

## S7 持续语音转文字

短按 S7 后，开发板通过已绑定的小智连接持续发送语音，使用 `listen.start` 的 `realtime` 模式。识别结果在接收期间就逐条发送到共享时间线；服务端可分成多句，过长结果再按最多 1000 个 UTF-16 单元及 3000 个 UTF-8 字节拆成多条。这里只保留用户识别文字，不播放小智 TTS 或保存本轮音频。网络和首次绑定要求与 S6 相同。

按下任意键或触发静音／总时长上限后立即停止麦克风，将已采集的尾帧发完，并最多接收 20 秒尾句结果。识别任务终止后，再等待本轮文字的网页显示确认，期限为 12 秒。至少得到一条识别文字、且本轮全部文字都在至少一个已挂载的网页聊天组件提交到 DOM 后得到回执，才播报“成功”。没有识别文字、发生错误、只有部分文字送达或回执期限到时播报“失败”；云端保存成功本身不算网页送达。

使用时需打开新版网页的“语音”页。设备页、尚未打开聊天页的连接不会发显示回执；回执表示文字已提交到聊天组件，不表示用户已经阅读。网页回执丢失时会有限重试，断线重连后可重新确认。S7 开始提示期间按任意键会取消并播报失败；停止后的尾句或回执等待期间按键不会新开会话。S7 与 S5 普通录音、S6 小智对话、网页实时监听互斥。

失败后未确认文字保留在原 FIFO 中继续后台补传，文字后来送达也不会补播“成功”；只要队列未完全满，旧待发文字不阻塞再次短按 S7 开始新一轮。统计边界设在引擎实际接受新一轮开始时，开始提示期间也可能补传旧文字。旧文字的 ACK 先从旧队列消耗，不增加本轮显示确认数；本轮成功只比较本轮识别数、确认数及本轮未确认数，不以整个历史队列是否清空作为成功条件。稳定消息编号用于去重；已写入 `stt/pending` 的队首可跨重启补传，后续多条队列仍在 RAM，不能保证本轮全部文字或音频断电恢复。

状态 `voice.stt` 的 `received_texts`、`acked_texts` 分别统计本轮识别和显示确认的消息条数；`session_queued_texts` 是 FIFO 总数扣除旧轮剩余条数后，本轮实际仍在队列中的未确认条数，`queued_texts` 则包含旧轮和本轮全部待发文字。显式取消清空队列后，本轮队列数可为 0，但不会伪造已显示 ACK。`stage` 可区分 `delivery.no_text`、`delivery.offline`、`delivery.display_timeout`、`delivery.engine_failed` 和 `delivered`；若已有首个引擎错误，其阶段和错误码优先保留，不被后续交付结果覆盖。开始提示取消或引擎拒绝时不执行最终交付诊断回写；引擎开始错误保留，例如 `start.unavailable`、`start.busy`、`start.queue_full`。

## 已有血压与血糖记录

S7/S8 的测量编辑、双击查询和旋钮粗细调整入口已移除。已有板端 `health/history_v1` 数据及最多 64 条待同步历史保留，联网后继续通过 Wi-Fi 或选中的蓝牙网关补传；云端按稳定编号去重，收到确认并完成本地存储后才移出队列。不会因停用按键删除历史或补造旧测量。

设备页「下载历史 CSV」继续导出云端已同步的全部测量记录，包含编号、测量时间、时间状态、人物、项目、数值、单位、接收时间和开机后毫秒数。血糖单位为 mmol/L，血压为 mmHg；时间为 UTC ISO 格式。未校准设备时钟的测量时间留空并注明未知，接收时间不冒充测量时间；板端待同步数量仍单独显示。

## 五颗红灯

固件 0.4.22 起采用下表，已发布的旧固件灯效可能不同。全部 WS2812 点亮亮度为最低档 1%；慢闪是亮 0.5 秒、灭 1.5 秒（周期 2 秒）；1 Hz 是每秒闪一次，亮 0.5 秒、灭 0.5 秒。网页动画沿用同一节奏，不保证与实物相位同步。

| 灯 | 常亮 | 慢闪 | 每秒闪一次 | 熄灭 |
| --- | --- | --- | --- | --- |
| 灯 1 | 有未读语音 | 正在接收新留言或下载语音，优先于未读常亮 | 无 | 没有未读且未接收 |
| 灯 2 | 已设置每日闹钟 | 闹钟到点后 1 分钟 | 倒计时或正计时运行中 | 没有闹钟或计时状态 |
| 灯 3 | S5 录音、S6 对话或 S7 转写期间 | 有待发送／待重试的录音或文字 | 无 | 没有收音会话或待发内容 |
| 灯 4 | 无 | 网页实时监听实际采集中 | 无 | 实时监听未生效或已关闭 |
| 灯 5 | Wi-Fi 连接正常 | 正在连接／重试连接 Wi-Fi | 无 | 未连接 Wi-Fi |

灯 2 优先级：**闹钟到点 > 正／倒计时 > 已设置闹钟**。被覆盖的计时继续运行，1 分钟结束后恢复相应显示。灯 3 收音会话优先于待发送；S6/S7 的连接及结果等待期间也属于会话状态。

灯 1 在收到首次出现的留言信息后慢闪至少一个周期，下载语音期间持续慢闪；普通心跳、已有消息状态更新不会触发“接收”闪烁。未读数量可能随重连后的历史同步更新，不能把灯灭理解为已清空云端历史。

灯 5 按设备 Wi-Fi 连接状态判断：连接到路由器后常亮，正在连接或断线后自动重试时慢闪；没有 Wi-Fi 配置、Wi-Fi 已停止或暂停连接以重新配置时熄灭。持续重试期间保持慢闪。灯 5 不表示互联网或语音服务可达性，蓝牙网关和语音服务心跳不影响它；服务心跳仍用于语音功能的连通判断。

## S5 持续上传与保存

S5 是异步语音留言：需要开发板通过 Wi-Fi 直连云端，网页可以关闭。短按后先播开始提示，云端确认建立会话后打开麦克风；灯 3 录音时常亮，停止后的尾音上传／保存等待期间慢闪。按任意键停止，音频任务先交付最后不足一帧的 PCM，再传完缓冲，最后提交确切长度。云端完成持久化后才发布一条留言；网页重新打开时可查看，不显示录音中的临时消息，也不实时播放。

板端把 16 kHz 单声道 PCM 转为兼容历史留言的 8 kHz G.711 mu-law，使用固定 256 KiB 环形缓冲（约 32 秒音频），每次最多上传 8 个 768 字节分片。分片得到云端持久化回执后才从缓冲移除，回执丢失每秒重发同一请求；短时断线可以恢复。连续 30 秒无有效进展、采集错误或缓冲溢出会停止，不能继续丢帧假装成功。缓冲溢出时可排空已有有效部分并提交为中断；失联、断电或重启则由云端独立定时器在约 90 秒没有新数据后，将已收到部分保存为“录音传输中断”。没有收到音频的会话不生成空留言。尚在 RAM、未获云端确认的音频不保证断电恢复；旧会话清理前开始新一轮可能需等待。

S5 不再提供长按取消。录音中按任意键都停止并保存，后续按键不能撤回正在保存的尾音；不需要的已保存留言可在网页删除。开始提示或云端建立会话阶段按任意键仍可取消开始，空会话不生成留言。

默认无论录了多长都只发布一条。网页在已保存语音下点击“分割语音”，输入每条秒数并确认，将原留言替换为 2–100 条；总历史仍不能超过 5000 条。分割发生在云端，以采样范围引用原始音频，不重新上传或复制整个文件；支持跨原分片边界及再次分割，最后一条保留精确尾音。分割重试使用同一编号，历史淘汰不会删除其他分段仍引用的源音频。

采集连续静音 60 秒或总时长达到 60 分钟时自动停止并正常保存，保留结尾静音，不自动分条。采集上限之外，存储格式和平台资源边界仍保留：单条最多 `0x7ffff000` 个 8 kHz 采样（约 74 小时，WAV 小于 4 GiB），达到时停止并标为中断。实际保存还受云端空间、配额和网络限制。开发板历史回放使用固定窗口和 PCM 环形缓冲；网页顺序播放只预解码数秒，加载／导出 WAV 逐批生成 Blob，避免整条 PCM 数组。ZIP 最多 100 条或约 64 MiB 一包，更大的单条独立一包；ZIP32 超过 4 GiB 时提示先分割。

新 S5 不再写入 `voice_outbox`；旧固件留下的 8 槽、每条最长 20 秒的 Flash 录音仍保留，空闲时按旧协议补传，云端确认后才释放。网页自身麦克风仍保持 20 秒限制。S6／S7 使用上述任意键与自动停止规则，网页临时实时监听仍由网页开关控制。

## 实时麦克风

- 网页“打开实时监听 / 关闭实时监听”直接启停板载麦克风，是共享房间开关，默认关闭；其他网页同步状态。
- S7/S8 不控制网页实时监听开关，S8 独立控制正计时。为避免录音路径冲突，监听期间 S1～S5 暂停操作，S6/S7 不会开始小智对话或转写；已有普通录音、小智对话或 S7 转写时拒绝打开实时麦克风。
- 板端通过二进制 WebSocket 帧发送 16 kHz 单声道 PCM16，每 20 ms 一帧、320 个采样。
- 板端在同一有序 WebSocket 上同步发送 `realtime.start`，随后立即发送实时音频；云端 ACK 仅用于诊断。网页使用约 60 ms 抖动缓冲播放。
- 实时缓冲超过约 250 ms 时丢弃旧队列，避免延迟持续累积。
- 实时音频只通过语音房间转发，不写入云端历史或 Flash。
- 网页关闭开关、开发板 Wi-Fi 直连断开或心跳超时都会停止采集并同步关闭状态；启动 8 秒未成功会取消打开请求。
- 当前 PCM16 实时流要求开发板通过 Wi-Fi 直连云服务；蓝牙网关仍可承载历史语音和状态，但不承载实时音频。

## 提示音

提示音使用 `edge-tts-chinese` 生成后裁掉首尾长静音并转换为 8 kHz 单声道 μ-law。常规提示沿用云健男声 `zh-CN-YunjianNeural`、语速 `+35%`；既有音量数字沿用晓晓女声 `+20%`。闹钟时间和倒计时分钟使用完整短语，打包为 `prompts.bin`。S8 使用新增的开始正计时、总时长、小时和秒提示；闹钟旋律由本地正弦音符合成约 10 秒后打包，不依赖外部音乐。S7 结束使用成功或失败提示；闹钟保存或取消失败复用同一条“失败”音频。

资源包保留 167 条现用提示音，清理了 42 条无引用的旧监听／在线状态、测量、记账及转写提示，从 1,350,676 字节缩小至 986,582 字节。现用提示的 ID 与音频字节保持不变，已移除的 ID 保留为空洞，后续新增提示不得复用这些编号。`PROMPT_COUNT` 表示 ID 上界，并非资源包条目数；读取时按目录中的 ID 查找。

仅复用已有音频并清理停用项（无需调用 TTS）：

```bash
python3 scripts/build-voice-prompts.py --reuse-existing
```

`--refresh-index ID` 和 `--refresh-from ID` 使用固定提示 ID，`--refresh-first N` 按 ID 顺序选择前 N 条现用音频。指定 `--reuse-existing` 时会保留其他现用音频，并生成缺失项。

重新合成全部现用提示音：

```sh
python3 scripts/build-voice-prompts.py
```

## 网页

网页只保留两个入口：

- **语音**：统一时间线、网页录音、实时监听状态及开关、S1～S8 操作、五灯含义和限制说明。提供「下载全部语音 ZIP」和「顺序播放全部」；全部指云端当前保留的最多 5000 条混合消息中的全部语音，跳过文字，与网页已经加载的页数无关。网页首屏显示最新 50 条，可点击「加载更早消息」继续翻页；总条数和未读数覆盖整个群。ZIP 每包最多 100 条或约 64 MiB（超大的单条独立一包），文件按全局顺序和 UTC 时间命名；第一包完成后点击「下载第 N 包」继续。失败可重试当前包。连续播放先取得完整历史索引，再从最早到最新逐条下载播放，支持随时停止，网页播放不改变开发板未读状态。导出开始后新到的语音留待下次；若期间旧语音被清理会提示重试。
- **设备**：显示每日闹钟、倒计时、正计时和实时监听状态（计时数值随 USB／蓝牙完整设备状态更新，尚未收到时显示等待状态），以及血压血糖历史和记账历史 CSV 下载。USB、蓝牙连接按钮及状态集中放在折叠的「连接 Wi-Fi 与语音服务」配置区，顶部仅保留开发板在线状态和网页版本。

网页已移除手工文字输入、电脑槽位、灯光编辑、音频测试、性能、存储、分区、输入事件流和演示模式。

### 容量说明

5000 条均录满 20 秒时，云端原始压缩音频约 800 MB，另加数据库与索引开销；下载的 WAV 总计约 1.6 GB，分包保存。实际可用空间和请求额度以 Cloudflare 账户套餐、用量为准，达到平台额度可能导致上传失败。建议保留需要的本地 ZIP 备份。实时监听仍不保存音频。历史 outbox 的 8 条录音和 64 条旧版待同步测量记录仍保留；新 S5 使用云端分片保存，不增加离线 Flash 录音。
